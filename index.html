Have these open or on your machine first. Chasing a missing reference file halfway through is how drawings get half-finished and forgotten.

Three rules that govern everything below

1. Never rotate or move the geometry to make a view look right. The CADD Manual says it in capitals. Rotate the view, via UCS. The geometry stays where the coordinates put it.

2. Colour and linetype BY LAYER, never by entity. YYC plots through a colour-dependent CTB — the colour is the pen weight. Set anything by object and the drawing plots wrong on their end.

3. Nothing lives on layer 0 or DEFPOINTS except geometry inside a block definition.

Phase 1 · Out of Revit
1

Export the CAD files from Revit

Batch or individual, your call. Use the YYC CAD template and the correct Export Setup. Either name each file properly as you export it, or export them all and batch-rename at the end — but pick one, don't half-do both.

Shadi's note — open question

Untested idea: set the real-world geodesic coordinates in Revit from Location, and see whether the export then lands that far out from 0,0 in AutoCAD. Worth trying when there's time.

As it stands today: export, move, align, rotate. Steps 5 and 7.

2

Name the files — before you touch anything else

Format is the YYC drawing number + sheet number, with every period and dash stripped out.

Run this

YYCRENAME renames a whole export folder in one go. Run it from a blank drawing: AutoCAD can't rename a file that's open.

Manual method — the example behind the tool, and the fallback if a tool fails
-- YYC drawing number for this project: 24C024
A102        -->  24C024A102.dwg
A-201       -->  24C024A201.dwg
AD.201      -->  24C024AD201.dwg   demolition
M-201.01    -->  24C024M20101.dwg  mech, no separators
Shadi's note

Do this before you start on layers. Once you're deep in layer translation you will not want to be renaming files and re-pathing xrefs, and renaming a file you've already cleaned is how you end up doing a sheet twice.

Why it's strict

The drawing number is what makes each file unique sheet-to-sheet and project-to-project in the Airport Authority's archive. It's assigned by their PM at project start — for 24C024 it's already set. The filename you deliver is the filename they file forever.

Phase 2 · Sheet setup
3

Resize the sheet in Page Setup

Open the exported DWG. To be clear about what this step is: you are not swapping the titleblock. The titleblock that came out of Revit is correct. What's wrong is the sheet size — Revit doesn't export exactly to A0, so the page setup is off.

Fix it by importing the page setup from YYC Titleblock - Revit Export_A0 through Page Setup Manager. Applying it sets the sheet to a true A0.

Run this

YYCPAGESETUP applies the page setup and moves the sheet onto 0,0. If the sheet looks unchanged afterwards, type RE (REGEN) and the A0 size shows.

Manual method — the example behind the tool, and the fallback if a tool fails
Shadi's note

You only need to import it once — after that it's saved on your machine and available in every drawing. If you can't find it in the list, you haven't imported it yet on this workstation. It isn't project-based.

While you're in there

Sheet borders and titleblock belong in paper space. The plan, notes, dimensions and symbols belong in model space. The layout origin sits at the lower-left 0,0,0 of the sheet border, and layouts always plot at 1:1.

4

Move schedules to paper space with CHSPACE

Revit dumps schedules and sheet-level annotation into model space. They need to be in paper space. Do not skip this one.

Run this

YYCSCHEDULES does this for you. Click each schedule viewport's frame: what it shows moves to paper space at the same size and spot, then it offers to delete the empty viewport. Keep CHSPACE for anything left over.

Manual method — the example behind the tool, and the fallback if a tool fails
-- from inside the layout, with the viewport active
Command: CHSPACE        alias: CHSP
Select objects:          pick the schedules / sheet annotation
-- AutoCAD scales them automatically for the new space

When it's done, model space holds the drawing and paper space holds the sheet furniture. That separation is what makes the rest of the workflow behave.

Don't copy-paste

Copy-pasting between spaces doesn't rescale, so your schedule text ends up wildly wrong — and it silently breaks the association. CHSPACE handles the scale factor for you. Use the command.

Shadi's note

Very important, easy to skip, painful to fix later. Get it done while the drawing is still simple.

Phase 3 · Position
5

Land the drawing on the YYC grid

Your export sits near Revit's internal origin. The YYC grid sits out at the Local Airport Coordinate System — roughly N 18,415,271 / E 16,173,697 in millimetres. Which is why, as you'll see, your plan starts out miles from the grid.

Run this

YYCGRIDIN brings in the right grid for your profile (04 DTB or 20 ITB) at 0,0,0 as one block. On the first sheet of a terminal, YYCALIGNREC does the ALIGN with the same four clicks, never scales, and remembers the move. On every other sheet, YYCALIGNAPPLY repeats it with no clicks. Both also turn the drawing viewport (step 7). Don't MOVE by hand first: the recording only knows its own clicks.

Manual method — the example behind the tool, and the fallback if a tool fails

Bring the grid in

Open YYC Grid - 04 DTB Domestic.dwg
Command: COPYBASE      or Ctrl+Shift+C
Base point: 0,0,0       type it, don't pick it
Select objects: the grid

-- back in your export drawing
Ctrl+Shift+V            PASTEBLOCK - comes in as one block
Insertion point: 0,0,0

XREF works just as well if you'd rather. Either way the grid lands at its true coordinates, which gives you something real to align to.

Then move, then align

  1. Rough-move your drawing into the neighbourhood of the grid — it starts far away, so get it close first.
  2. Run ALIGN and use two matching points to seat it exactly.
Command: ALIGN
Select objects:                 your plan
First source point:             a grid intersection on your plan
First destination point:        same intersection on the YYC grid
Second source point:            a second, distant intersection
Second destination point:       its match
Third source point:             <Enter> to skip
Scale objects to alignment points? [Yes/No] <N>: N
Answer No to the scale prompt

Say Yes and AutoCAD will resize your entire plan to force the two points to match — quietly, and by a fraction you won't notice until someone dimensions off it. Always N.

Pick your two alignment points far apart. Two points close together will look aligned locally and be visibly out at the other end of the building.

Shadi's note

Pasting as a block rather than raw geometry is deliberate — it stays one selectable object, so in the next step you delete it in one click instead of hunting stray grid lines through your drawing.

6

Delete the grid, purge, audit

The grid block was scaffolding. Once you're aligned, it goes.

Run this

YYCGRIDOUT deletes the grid block and its definition. YYCCLEAN deletes empty text, purges three times and audits. YYCFIND0 lists any $0$ names left from binding.

Manual method — the example behind the tool, and the fallback if a tool fails
Delete the pasted grid block   one click, because you pasted it as a block
Command: PURGE            tick "Purge nested items", run it twice
Command: AUDIT            Fix any errors detected? Y
Shadi's note

Purge and audit here, mid-workflow, not only at the end. The grid file drags in its own layers, blocks and linetypes, and clearing them now means they don't pollute your layer list when you get to LAYTRANS — where a clean list is the whole game.

7

Set up the viewport and the rotation

Here's the problem this step solves. Your plan is now correctly positioned but sitting at roughly 45° — because YYC's building drawings run parallel to the segmented radial grids, not to true north. So the viewport shows the plan skewed and in the wrong spot.

The target: the sheet reads project north; model space stays true north.

Run this

The rotation is now done in step 5. YYCALIGNREC and YYCALIGNAPPLY turn the drawing viewport by exactly the angle of the move and give it a matching YYC Project North UCS, the same result as UCS OB + PLAN: the sheet reads as exported, project north up, model at true coordinates, and crosshairs and ortho follow the sheet. What's left here is YYCVPLAYERS, a scale check, and YYCVPLOCK, which offers to snap a drifted scale back. Note: if there are more VIEWPORT# layers than viewports (for example, after YYCSCHEDULES deleted some), run YYCVPLAYERS again, then YYCCLEAN to purge the empty ones.

Manual method — the example behind the tool, and the fallback if a tool fails
  1. Unlock the viewport.
  2. Pan the view to the right part of the building.
  3. Set the viewport scale.
  4. Rotate the UCS, not the drawing, so the plan sits square on the sheet.
  5. Set the viewport scale again — confirm it didn't drift.
  6. Lock the viewport.

Rotating the view properly

-- double-click inside the viewport to activate it
Command: UCS
  option OB and pick a line along the radial grid, or
  option Z and type the rotation angle
Command: PLAN
  <Current UCS>: C       regenerates plan view to the rotated UCS
The geometry does not move

"DO NOT ROTATE OR MOVE THE ELEMENTS THEMSELVES." — CADD Manual §2.4, their capitals. Rotating geometry destroys the coordinate relationship to every other drawing on the site. The UCS is the only correct tool here.

Shadi's note

I keep viewports from previous projects and copy them across — it's the fastest route when the rotation matches. But each area has its own angle off north, so a new area like NPSC needs building from scratch. Do it once, carefully, then copy that viewport into every other sheet in the set.

Two things YYC checks

Viewports go on a layer named VIEWPORT1, VIEWPORT2, VIEWPORT3… set to do not plot.

On delivery, the main layout must be the active tab and every viewport locked and set to the correct scale. An unlocked viewport is a failed deliverable — and it's the easiest thing in this document to forget.

The UCS: what right looks like

There are two UCSs on a YYC sheet, and they should be different. Inside the drawing viewport, the UCS is turned to match the plan (the YYC Project North UCS). On the sheet itself (paper space), the UCS stays at World.

Check it in ten seconds: double-click into the drawing viewport. The crosshairs should line up with the plan's grid lines, and ortho should draw along the walls. Double-click outside the viewport. The crosshairs should be square to the sheet border again.

If the sheet's crosshairs are tilted in paper space, the paper UCS was turned by mistake. Stay in paper space, type UCS, then W. If the viewport's crosshairs don't follow the plan, run YYCVPUCS. It only touches the drawing viewport, never schedules or keyplans.

Phase 4 · Layers
8

Fix the layers

The longest phase, and where compliance is actually won or lost. There are two separate problems, and they need different tools.

Problem one: the YYC standard has more and different categories than Revit maps to. Problem two: individual objects land on the wrong layer even when the layer mapping was right — a habit of MEP families in particular.

Run this — the Layer Mapper workbook

The toolkit replaces most of 8a and 8b with one round trip through Excel. You only decide each export layer once, ever.

1. YYCLWDEFAULT.  2. YYCLAYXL: AutoCAD writes every layer into the Map sheet of YYC Layer Mapper.xlsx and opens it.  3. Work down the red CHOOSE rows and pick a YYC layer from the dropdown in the yellow YOUR CHOICE column. Leave it blank if you're not sure; YYCLAYWALK shows it to you later. To merge, pick a layer that's already in the drawing; the Action column shows Merge into …. Save.  4. YYCLAYMAP applies it all and remembers it.  5. YYCLAYWALK for whatever you left blank: Show it isolates the layer, pick its YYC layer, Map.  6. YYCLAYSYNC sets colour, linetype and lineweight to the standard.

On the next drawing, everything you've mapped before comes back as REMEMBERED (blue). Revit numbers like A-WALL-3 go automatically. The dropdown holds all 691 layers from the YYC CADD Manual v6.2, including *-ANNO-* for every discipline.

Manual method — the example behind the tool, and the fallback if a tool fails

8a · Layer Translator — LAYTRANS

The Layer Translator remaps layer names and layer properties in one pass, then converts everything sitting on them. Manage tab → CAD Standards panel → Layer Translator, or just type LAYTRANS.

Shadi's note — one pass per job, not one big pass

It's tempting to map everything and hit Translate once. Don't. Mappings overlap, and layers get missed in ways you won't spot until QA.

Give each translate a single job. One pass for the titleblock lines. One for construction lines. One for grid linetypes. One for layer colours. One for the heavy and thin lines the titleblock exported as separate layers that need merging into one. Run it, check it, then start the next.

And save the mapping every time. A floor plan mapping and an RCP mapping are different animals — build the library once and the second sheet of each type takes minutes.

Turn the Settings checkboxes on

Force object colour / linetype to BYLAYER isn't cosmetic. YYC explicitly requires colour and linetype set by layer and not by entity, so files can be referenced and re-plotted correctly. Those two checkboxes do that enforcement for free while you're already translating.

Translate objects in blocks matters too — otherwise geometry nested inside blocks keeps its old layers and quietly fails the check.

Set lineweights back to Default

Revit stamps explicit lineweights on export — we found LineWeight009, 025 and 030 on 18 of 21 layers in the sample. The YYC standard is ByLineWeightDefault on essentially every layer, because thickness comes from the colour through the CTB.

Best fixed once in the Revit export setup rather than per sheet forever. Until then, correct it in the Edit dialog as you map.

8b · Check against the comparison spreadsheet

Open the Layer Properties Manager, click in the layer list, select all, and Ctrl+C — no export needed. Paste into the PasteExport tab of the comparison workbook and it flags what isn't in the YYC standard or is on the wrong properties.

With the toolkit you can skip this: YYCLAYXL sends the layers to the Layer Mapper workbook for you, and the standard check runs again in YYCQA. The modifier note below still applies, and the toolkit already knows the modifiers.

Shadi's note — modifiers

Layers carrying a status modifier sometimes don't get picked up. A-DOOR-DEMO is A-DOOR plus the DEMO modifier — legitimate, just not in the base list. Add them once and you're fine from then on.

What the manual says (4.1.6): a status modifier goes in as a fourth field, or replaces the minor group. It gives no colour or linetype for modifier layers, and only -NPLT has a rule: no plot. So the toolkit accepts any YYC layer plus a modifier, checks its lineweight and plot, and leaves its colour and linetype to you. A red dashed A-WALL-DEMO stays red dashed. Lineweight stays Default for modifier layers too: the manual sets every pen weight by colour through the CTB, so if demolition should plot lighter or heavier, change its colour, not its lineweight. In the Layer Mapper, a typed A-WALL-DEMO shows "Wall + Demolition (modifier - OK)". Remember colour is pen weight through the CTB, so a new colour also changes how heavy it plots.

Valid modifiers: DEMO · EXST · FUTR · MOVE · NEWW · NICN · NPLT · PRPS · RELO · TEMP

8c · Walk the layers — LAYWALK

Correct layer names don't mean correct layer contents. MEP is the usual culprit: the family itself exports to the right layer, but its annotation symbol lands on a generic annotation layer. No spreadsheet catches that. You have to look.

The toolkit can't do this part for you. YYCLAYWALK fixes layer names; this walk checks what's on them. Its Show it button isolates a layer the same way, if you'd rather stay in one window.

Command: LAYWALK
-- isolates one layer at a time so you can see what's actually on it
-- tick "Restore on exit" before you close the dialog

also useful:
LAYISO     isolate the layer of a selected object
LAYUNISO   undo that
LAYMRG     merge one layer into another and delete the source
LAYDEL     delete a layer and everything on it
SETBYLAYER force colour/linetype/lineweight back to BYLAYER
Run SETBYLAYER before you walk

Known AutoCAD behaviour: LAYWALK can fail to display objects whose colour is set by entity rather than by layer — so you'll walk a layer, see nothing, and conclude it's empty when it isn't. Ctrl+A then SETBYLAYER first. It fixes the display problem and satisfies the YYC by-layer requirement in the same stroke.

Shadi's note

This is slow and there's no shortcut — you're scanning every layer to confirm what's on it. Budget the time honestly rather than rushing it, because this is exactly the class of error that comes back from YYC as a rejected submission.

Phase 5 · Close out

9 · Final QA sweep

Straight from CADD Manual §5.15. This is what they check on receipt — walk it on every sheet.

Run this

YYCCLEAN → YYCFINAL (locks viewports, main layout active, zoom extents) → YYCQA. QA changes nothing. Pick This drawing or Folder (every DWG, opened read-only). It writes YYC QA Report <date>.xlsx next to the drawings: Summary shows each drawing with OK / FIX per check, Details says what was found and how to fix it, Checks explains each one. Repeat until every row is PASS. AUDIT, real linetypes and real circles are still checked by eye.

  • Purged of all unused definitions — layers, text styles, dimension styles, layer filters, blocks. Blank layers are not permitted in a delivery.
  • No empty definitions — no empty text objects, no blocks without geometry.
  • Nothing on 0 or DEFPOINTS, except inside block definitions.
  • AUDIT comes back clean. No detectable errors.
  • Colour and linetype BY LAYER throughout — SETBYLAYER if in doubt.
  • Lineweights at Default, letting the CTB drive thickness.
  • Dimensions fully associative. Manually overridden or non-associative dimension text is explicitly not acceptable. Worth a spot-check on Revit-exported dims.
  • Linetypes are real linetypes from CAA.LIN — not dashes drawn as individual line segments. Circles are circles, not polyline approximations.
  • Viewports on the VIEWPORT# layer, set to no-plot, locked, at correct scale.
  • Main layout active, and the file prints with no additional page setup required.
  • ZOOM Extents — nothing stranded off-sheet.
  • One eTransmit zip per discipline, named to the project pattern, with the File Description PDF alongside.

File description and transmittal

Run this

YYCTRANSMIT on the delivery folder makes every zip in one go, named exactly as above. It asks the stage and phase, and takes the discipline from each file name. Each zip carries the drawings, their xrefs (re-pathed, not bound), the CAA fonts and CAA.SHX, the CTB and a Transmittal.txt. Open one and compare it with a normal ETRANSMIT before the first real delivery.

Run this

YYCFILELIST on the delivery folder writes filelist.txt, flags any badly named file, and writes FileDescription_list.txt: every drawing with its sheet title, grouped by discipline, ready to paste under the header block. Then YYCFILEDESC combines everyone's lists (their .txt / .docx, or a folder of their DWGs) into the final File Description, Word and PDF, using your last one as the template. You still have to collect the consultants' lists.

Manual method — the example behind the tool, and the fallback if a tool fails

First, collect the lists from every consultant

You can't write the File Description from your own folder. Go to each consultant — electrical, mechanical, structural — and get their drawing list and exact file names. Names must match the DWGs they actually send, character for character, because the File Description is the index YYC files the package against.

Shadi's note

Ask for this early, not at the end. Chasing four consultants for filenames while a submission deadline runs down is the worst part of this whole process, and it's entirely avoidable. Request the list as soon as the issue date is set.

Shadi's note — be consistent

Pick the pattern and hold it across every discipline and every issue on the project. Underscores between fields, no spaces, no dashes. 24C024_Record_PH1_AR.zip and 24C024_Record_PH1_ME.zip should differ by exactly two characters and nothing else.

Mixed-up zip names are how a discipline's package gets logged against the wrong stage — and nobody notices until someone downloads Record and gets BID drawings.

Two-letter zip codes, one-letter file codes

The zip uses AR / EL / ME / ST. The DWG filenames and layer names use the single letters A / E / M / S. Different systems, both correct in their own place — don't harmonise them.

LISP toolkit & test status

One file, YYC-CADTools.lsp, with a command for every step that can be automated. It was built from the team's existing LISP routines, with the hard-coded paths taken out, plus a few new ones where the process had gaps. Each command appears under its step above, and its badge says whether it has been tested yet.

Built on ActiveX

Every tool works through AutoCAD's ActiveX object model (the vla- functions). It reads and changes the drawing's layers, layouts and viewports directly, instead of typing commands at the command line. So the same code runs on the drawing you have open or on a whole folder through YYCBATCH. The template and the layer reference are read straight from disk without being opened. Needs full AutoCAD on Windows; it won't run in AutoCAD LT or on a Mac.

Download the add-in (YYC-CADTools-addin.zip)   or just the .lsp file, for updates

Install — once per machine

  1. Close AutoCAD. Unzip the add-in.
  2. Press Windows + R, type %APPDATA%\Autodesk\ApplicationPlugins and press Enter. Create the ApplicationPlugins folder if it isn't there.
  3. Copy the whole YYC-CADTools.bundle folder into it. Start AutoCAD. The command line should say YYC CAD Tools … loaded. Type YYCHELP to see every command in order, with a Run button. The ribbon gets a YYC Export tab: Setup · Sheet · Grid · Viewports · Layers · QA · Deliver, every command in process order. No tab? Right-click the ribbon → Show Tabs → YYC Export.
  4. Updating: copy the new YYC-CADTools.lsp into YYC-CADTools.bundle\Contents over the old one, then restart AutoCAD. Your profiles and settings are stored for your Windows user, so updates never touch them.

The kit folder

The kit folder is where the YYC reference files live. In the kit it's 3 - Kit folder; its What each file is.txt lists everything. The tools search it, subfolders included, so you pick each file from a list instead of browsing every time.

Profiles — one per terminal or area

A profile holds one set of kit files plus the recorded move onto the YYC grid. Make one for Domestic (04 grid) and one for International (20 grid). There is one command for everything about profiles: YYCPROFILES. It opens a window: pick a profile on the left and change it on the right. Type the description and drawing number straight into the boxes. Click … next to any file to browse for it. Page setup, plot style, scales, schedule margin and fonts are behind More settings…; you set those once. Grid move picks whether the profile uses its own recorded move or the same move as another profile (same terminal, same export position). Fill empty files from the kit folder finds the rest. Add copies the selected profile, Remove takes one off the list, and Save + use switches to it. Every command prints Profile: … first, so you always know which one you're on.

First time

1. Install the add-in.  2. YYCSETUP (opens the profiles window): click … by Kit folder, click Fill empty files from the kit folder, check the Grid, type a Description, click Save + use.  3. On the first export: YYCGRIDIN → YYCALIGNREC (four clicks, answer Main for viewports) → YYCGRIDOUT.  4. Every other sheet from that terminal: YYCALIGNAPPLY, no clicks.

Coming back — profiles already set up

1. Open the export.  2. YYCPROFILES: if the right profile has the *, close the window; if not, pick it and click Save + use this profile.  3. Work down the run order below. YYCALIGNAPPLY reuses the recorded move.  A new terminal or area? In YYCPROFILES type a name in New, click Add, pick its grid with …, and record its move once with YYCALIGNREC.

Shadi's note — how testing works

Test one command at a time on a copy of a real export. When it does what the step says, it's Tested. When it doesn't, it's an Issue, with a note saying what happened. Statuses live in one list at the bottom of this page's source (TOOLS), so updating one is a one-word edit.

Run the rest of that terminal's sheets through YYCBATCH: Pagesetup, then YYCSCHEDULES on each sheet, then Align → Vplayers → Lwdefault → Laysync → Clean. Finish with one batch of Final → Qa and read YYC_QA_Summary.csv.

Ground rules every command follows

Checks only report. YYCQA and YYCZERO change nothing. Fixes can be undone in one step: viewport and layer commands are wrapped in a single undo. Batch runs back up first: YYCBATCH copies the folder before it touches anything, saves as AutoCAD 2018 and writes YYC_Batch_Log.txt.

Layer naming, in short

AIA long format: Discipline - Major - Minor - Status, four characters per group.

Disciplines: A Architectural · C Civil · E Electrical · F Fire Protection · G General · I Interiors · L Landscape · M Mechanical · P Plumbing · S Structural · T Telecom · V Survey

Same item type always on one layer — a full-height wall is A-WALL or A-WALL-FULL, never both in the same set. New layers need Spatial Data Services approval before use.
